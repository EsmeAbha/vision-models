# FinAI document workspace

Run from the project root:

```powershell
.\.venv\Scripts\python.exe workspace_server.py
```

Open **http://127.0.0.1:7880**. The original Gradio application on port 7860 runs separately.

## Analyst workspace

Upload PDFs or document images, or use a file/folder inside `uploads/workspace`. Choose a preset, preview the plan, and confirm execution. Utility Bill Extraction is selected by default and supplies its own task when the task box is blank. Choose Extract Requested Fields to specify custom columns and row granularity in natural language. These prompts control extraction only; they cannot run arbitrary commands or access other files. Job notes remain reviewer context.

Two executable skills are registered from `workspace_skills/*/skill.json`, with their instructions in the adjacent `SKILL.md` files. `workspace_extraction.py` reuses `readers.py` for native text and vision transcription, and `ai_extract.ask_model` for structured extraction. Every page is considered independently, so scanned pages inside mixed PDFs are read automatically. The runtime checks the installed local model service and reports actionable failures without leaking technical paths. It does not download models.

Utility Bill Extraction creates a fixed 23-column bill layout, one row per bill/account/period. Extract Requested Fields follows the analyst's column request. Both create a workbook with Extract, Evidence and Review sheets, a structured JSON result and a source transcript. The job screen previews the first 20 rows. Leading-zero identifiers and printed amounts stay literal. Missing required fields and untraceable values are flagged. All model-generated results require human review: a text match is not proof of semantic correctness, and a vision transcript is not independent verification of the original image.

The local processing worker uses the existing geometry, table, validation and recipe engines. It creates unique job directories under `outputs/workspace`, including XLSX workbooks, quality reports, exceptions and SHA-256 provenance. No destination is overwritten. Job state, review notes, studio drafts and audit events persist in a local SQLite database. Broad job lists omit document names.

Quality-only mode accepts PDF sources and one prepared XLSX workbook. It checks workbook readability, cell errors and external links without repeating extraction. Because an approved source-to-cell mapping service is not connected, it creates a blocking finding instead of claiming full reconciliation. Acknowledging findings never changes a failed QC result to a pass. Downloaded reports are immutable run-completion snapshots; later review notes live in the job record.

Automatic image-based reading is connected for the two field-extraction skills. Legacy table and layout presets remain digital-PDF-only. Arbitrary workbook-template mappings and custom output destinations are not connected.

## Technical studio

Includes skill catalog, skill builder, application registry, workflow composer, template/macro contracts, configuration test bench, release review, permission/vault overview, audit observability and security console. Drafts are stored independently from repository recipes. Configuration checks validate required fields and the registered workflow sequence. They do not run untrusted code or certify extraction accuracy. Production approval/publishing is intentionally unavailable without independent reviewer identities.

## Local security boundary

This is a **single-user development workspace**, not a multi-user enterprise deployment. Any user who can access this device's loopback application can establish a local owner session. The application is bound to `127.0.0.1`, checks Host and Origin, uses an HttpOnly SameSite session cookie and requires that session for APIs and downloads. Filesystem intake resolves paths against a dedicated approved root. Output filenames are generated by the server. Source strings are written as literal workbook values.

Current limits: 20 uploaded files, 30 MB per file, 30 pages and 48,000 characters per field-extraction document, 40 megapixels per image, 150 pages per native-table extraction PDF; QC workbook expansion is limited to 100 MB and inspection to 500,000 cells. Inputs exceeding field-skill limits fail explicitly instead of silently truncating. Worker execution is single-threaded in-process and is not OS-isolated. No scheduled retention, malware scanner, enterprise identity provider, vault resolver, enforced OS egress policy or isolated macro runner is provided. Security policy drafts do not change these runtime controls. Do not expose this development server as a shared enterprise service.

## Verification

```powershell
.\.venv\Scripts\python.exe test_workspace.py
.\.venv\Scripts\python.exe test_workspace_fields.py
# Optional real inference against installed models; generated synthetic data only:
.\.venv\Scripts\python.exe test_workspace_fields.py --live
node test_workspace_ui.cjs
```

The Python suite uses generated synthetic fixtures in an isolated test directory. It covers PDF-to-workbook output, output hashes, QC exceptions, safe errors, path containment, session/origin checks, workflow compatibility and release gates. The JavaScript check requires the server running on 7880 and exercises bootstrap plus all 16 route renderers. It is not visual browser verification.
